# 10 How apps consume this

Two ways to get the components. Both end at the same imports and the same `tokens.css`.

| | Package link | Vendored copy |
|---|---|---|
| Used by | Apps inside the Timebase repo (Historian and the other Timebase UIs) | Apps outside it (ClaudeP) |
| How | `"@timebase/react-ui": "link:<path to Timebase.Core.React.UI>"` in `package.json` (the library README says `workspace:*` in the repo's workspace) | A generated snapshot under `src/design-system/` |
| Import | `import { TimebaseButton } from "@timebase/react-ui"` | `import { TimebaseButton } from "@/design-system"` |
| Styles | `@import "@timebase/react-ui/styles/tokens.css"` plus `@source "../node_modules/@timebase/react-ui/src"` | `@import "./design-system/styles/tokens.css"` |
| Updates | Automatic: the link points at live source | Explicit refresh, pinned to a commit |

Pick the package link when the app lives in the Timebase repo. Use the vendored copy only when it cannot.

## Package link

Peers: `react` and `react-dom` ^19, `react-router-dom` ^7, `tailwindcss` ^4, `react-aria-components` ^1.17. Heavy sub-paths (`/agent`, `/json-editor`, `/topology`, `/graph`, `/hubs`, `/signalr`) bring their own optional peers; import them only when used.

Minimum wiring, as Historian does it:

1. `index.html`: the theme boot block from [08-global-styles.md](08-global-styles.md), before any stylesheet.
2. `main.tsx`: the `@fontsource` imports ([03-typography.md](03-typography.md)) before `./index.css`; clear the inline background; follow OS theme changes while no preference is stored.
3. `index.css`: tailwind, tokens, `@source`, `body { margin: 0 }`. Nothing else.
4. Shell from the library: `TimebaseAppShell`, `TimebaseSidebar` and parts, `TimebaseWorkspaceShell` (tabbed apps) or `TimebaseTopbar` (page shell), one `TimebaseToastStack` and `AddToastContext`.
5. Root `TimebaseErrorBoundary variant="page"` and one `variant="region"` per tab.
6. ESLint: `import timebaseConfig from "@timebase/react-ui/eslint"` plus the token rule below.

## Vendored copy

How ClaudeP does it, and the rules that keep it honest.

- The snapshot is generated by `pnpm vendor:design-system [path to Timebase.Core.React.UI]`. The script reads the entry files from an `ENTRIES` list, follows every relative import, copies the files byte for byte, and rewrites `src/design-system/README.md` with the source path, package version and **commit hash**.
- **Never edit a vendored file.** Not for a bug, not for one class. The change goes into the Timebase repo first, then the snapshot is refreshed. A hand edit is lost on the next refresh and makes the copy lie about its commit.
- `index.ts` is the one file that is the app's own: a barrel that exports only the files copied, so the bundle carries nothing it does not use. The refresh keeps it.
- Add a component by adding its file to `ENTRIES` and exporting it from `index.ts`, then refresh. Do not copy a file in by hand.
- Paths and public APIs match the source, so moving to the package is an import-path change: `@/design-system` becomes `@timebase/react-ui`.
- After a refresh run the app's typecheck, lint and tests. Record the new commit in the commit message.
- The folder is excluded from lint (`globalIgnores(['src/design-system', ...])`), because it is generated from a repo with its own rules.
- A vendored app has a smaller component set than the package (41 files at the commit this spec was read against). If a pattern in this spec says "in Core, not in the vendored set", vendor it. Do not rebuild it locally.
- Anything the app builds on its own (ClaudeP's `Callout`, `DataTable`, `SegmentedControl`, field rows) is app code, lives outside `src/design-system/`, and is built from tokens and the shapes in [07-proposals.md](07-proposals.md).

## The token lint rule

State of play: the library's shared ESLint config (`eslint-config.js`) is the standard recommended sets plus React hooks and refresh. I found no rule in it that blocks a hard-coded colour. The "no raw hex" rule is a convention written in the library README and the colour file. Nothing enforces it today.

This spec makes it a rule. The check below is a `PROPOSAL` for the shared config. I ran it against a scratch file with ESLint 9.39.5: it flags a hex literal in a string, a hex in a template literal, a Tailwind palette class (`bg-red-500`) and `rgb(` or `hsl(` calls; it passes token classes (`bg-card`, `bg-primary/10 hover:bg-accent`) and `var(--tb-color-*)`, and skips `src/design-system/`. Regex backslashes do not survive esquery's selector parser, so the patterns avoid them.

```js
// eslint.config.js, after the shared config
{
  files: ['src/**/*.{ts,tsx}'],
  ignores: ['src/design-system/**'],
  rules: {
    'no-restricted-syntax': [
      'error',
      { selector: 'Literal[value=/#[0-9a-fA-F]{3,8}(?![0-9a-zA-Z])/]', message: 'Hard-coded colour. Use a token utility such as bg-card or text-muted-foreground.' },
      { selector: 'TemplateElement[value.raw=/#[0-9a-fA-F]{3,8}(?![0-9a-zA-Z])/]', message: 'Hard-coded colour. Use a token utility.' },
      { selector: 'Literal[value=/(?:bg|text|border|ring|fill|stroke|from|to|via)-(?:red|orange|amber|yellow|lime|green|emerald|teal|cyan|sky|blue|indigo|violet|purple|fuchsia|pink|rose|slate|gray|zinc|neutral|stone)-[0-9]{2,3}(?![0-9])/]', message: 'Tailwind palette class. Use a token utility.' },
      { selector: 'Literal[value=/(?:rgb|rgba|hsl|hsla)[(]/]', message: 'Hard-coded colour function. Use a token utility.' },
    ],
  },
}
```

Limits: it can false-positive on a string such as `"#add"` (valid hex length). Use an inline disable with a reason for the documented exceptions (the FOUC boot snippet, WebGL canvas colours). It does not check CSS files; add Stylelint's `declaration-property-value-disallowed-list` for hex and `rgb(` in app CSS. It does not check radius, shadow or motion literals; a review catches those ([11-review-checklist.md](11-review-checklist.md)).

Add the layering rule the library states in `docs/Primitives.md`: apps do not import `react-aria-components`.

```js
'no-restricted-imports': ['error', {
  patterns: [{ group: ['react-aria-components', 'react-aria-components/*'],
    message: 'Use the Timebase wrapper. If none exists, propose one (see design-system/timebase/07-proposals.md).' }],
}],
```

Historian passes this today (no file imports RAC or `lucide-react`). ClaudeP does not: seven of its own files import RAC (`Form`, `Table`, `ToggleButtonGroup`, field parts), mostly for patterns the vendored set lacked (see the appendix).

## Updating this spec

- A value changes in the library first, then here, then the vendored copies are refreshed.
- Every table cites its source file. Keep the citation when a value changes.
- A `PROPOSAL` is removed from [07-proposals.md](07-proposals.md) when the component ships, and its row moves to [06-components.md](06-components.md).
